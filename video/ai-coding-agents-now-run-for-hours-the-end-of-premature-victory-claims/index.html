AI Coding Agents Now Run for Hours: The End of Premature Victory Claims

Last time an AI system could run autonomously for hours on a single coding task, it was a hacky for-loop called Ralph-loop. OpenAI Codex and Hermes just changed the game—agents now persist goals across turns, judge their own work, and refuse to declare victory until the job is actually done. The implications stretch far beyond code: this is the first glimpse of AI that can handle ambiguous, long-running projects without human hand-holding.

Why "Just Keep Prompting" Was Holding AI Back

Until now, AI coding agents suffered from a fatal flaw: they were too eager to please. Ask an agent to "fix all failing tests in your repo," and it would spend 10–15 minutes on the task, then return with a confident "Done!"—only for you to discover half the test suite still broken. The workaround was brute-force: wrap the agent in a programmatic loop (like Ralph-loop), manually define stop conditions, and hope it didn’t get stuck in a cycle of superficial fixes.

This approach had three critical limitations:

  • No self-awareness: Agents couldn’t evaluate their own progress, leading to premature completion claims.
  • Rigid scoping: Tasks had to be hyper-specific; ambiguous goals like "cut Docker image size by 60%" were out of reach.
  • Human bottleneck: Users had to manually re-prompt the agent, turning automation into a tedious back-and-forth.

Inside the Persistent Goal System: Architecture, Training & Key Design Choices

The new persistent goal features in OpenAI Codex and Hermes agent represent a fundamental shift—from static loops to adaptive, self-judging workflows. Here’s how it works:

  • Dual-LLM architecture: A primary agent handles task execution, while a secondary LLM acts as a "judge" to evaluate completion. This mirrors the "critic" pattern in reinforcement learning but applied to real-time code generation.
  • Stateful context: Unlike Ralph-loop’s stateless iterations, the system maintains a persistent memory of the goal, past actions, and intermediate results. Each loop feeds the agent a prompt enriched with:
    • Original goal definition
    • Current state of the codebase
    • Previous attempts and outcomes
  • Dynamic stop conditions: The judge LLM uses a structured prompt to assess completion, with criteria like: 
    "Definition of Done: All test cases pass with no regressions."
    "Output Format: JSON with {status: [complete|incomplete], reasoning: string, next_steps: array}"
  • Exploratory mode for ambiguous tasks: For goals like "reduce Docker image size," the agent is granted permission to experiment—trying multiple approaches (e.g., multi-stage builds, dependency pruning) and iterating until the target is met.
  • Time and iteration limits: While the system can run for hours, safeguards prevent infinite loops (e.g., max 24 hours or 100 iterations).

The transcript doesn’t specify training details, but the judge LLM likely leverages the same base models as the primary agent (e.g., GPT-4 for Codex), fine-tuned on synthetic datasets of coding tasks with labeled completion states.

What This Means in Practice: Use Cases & Industry Impact

For developers, this is the first taste of true automation—not just a smarter autocomplete, but an agent that can own entire workflows. Imagine:

  • Onboarding new engineers: Instead of spending weeks ramping up on a codebase, a persistent goal agent could generate a "guided tour" of the repo, explaining architecture, dependencies, and key design choices—then answer follow-up questions in real time.
  • Legacy system modernization: Companies with decades-old codebases can now offload tedious tasks like dependency updates or framework migrations to agents, freeing engineers for higher-value work.
  • Startup prototyping: Founders can go from idea to functional prototype in hours, with agents handling everything from frontend scaffolding to backend API integrations.

Beyond coding, the persistent goal architecture hints at a future where AI agents tackle long-running, ambiguous tasks in other domains—think:

  • Scientific research (e.g., "explore this protein folding space for novel drug candidates")
  • Creative work (e.g., "write a novel that blends cyberpunk and solarpunk themes")
  • Business operations (e.g., "optimize our supply chain for cost and carbon footprint")

Current Limitations & What Researchers Still Need to Solve

Despite the breakthrough, the system isn’t without flaws:

  • Judge LLM bias: The secondary LLM may inherit biases from its training data, leading to false negatives (e.g., rejecting valid solutions) or false positives (e.g., accepting superficial fixes).
  • Context window limits: For very long-running tasks, the agent’s memory of past actions may degrade, causing it to repeat mistakes or lose track of the goal.
  • Exploration vs. exploitation: Ambiguous tasks require a balance between trying new approaches and refining existing ones—current implementations may err toward one extreme.
  • Cost and latency: Running two LLMs (agent + judge) for hours is computationally expensive, limiting accessibility for smaller teams.

The Road Ahead: Where This Research Points

Persistent goal agents are a stepping stone toward fully autonomous systems—AI that can not only execute tasks but also define them. The next frontier? Agents that:

  • Break down ambiguous goals into sub-tasks without human input (e.g., "build a SaaS app" → "design DB schema, implement auth, create UI").
  • Collaborate with other agents, each specializing in different domains (e.g., one for frontend, one for backend).
  • Learn from failures, refining their approach over time (e.g., "last time I tried X, it didn’t work—this time, I’ll try Y").

For now, this is the closest we’ve come to an AI that can truly work for you—not just assist, but own the entire lifecycle of a project.
