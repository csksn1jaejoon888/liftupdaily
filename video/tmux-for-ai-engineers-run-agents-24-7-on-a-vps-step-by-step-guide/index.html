Tmux for AI Engineers: Run Agents 24/7 on a VPS (Step-by-Step Guide)

By the end of this guide, you’ll have a Tmux session running on a VPS—keeping your AI agents like Codex or Hermes alive for hours (or days) without needing your laptop open. No more lost progress when your battery dies or your Wi-Fi drops. Here’s how to build it.

What This Tool Lets You Build

  • Persistent AI agents—Run Codex, Hermes, or other tools for days without interruptions, even if your local machine shuts down.
  • Multi-agent workflows—Split your terminal into panes to manage multiple agents working on different tasks simultaneously—like a refactor in one pane and a new feature in another.
  • Remote development—Offload heavy workloads to a VPS, freeing up your local machine while keeping full control via SSH.

Requirements Before You Start

  • A terminal (macOS, Linux, or WSL on Windows).
  • Basic command-line familiarity—you should know how to cd, ssh, and edit files.
  • A VPS (recommended: KVM2 plan from Hostinger or similar—transcript confirms this is sufficient).
  • Tmux installed—we’ll cover this in the steps, but if you’re on macOS, brew install tmux will handle it.
  • An AI agent like Codex or Hermes (optional, but the guide assumes you’re using one).

Complete Tmux Tutorial

1. Install Tmux Locally

Open your terminal and run:

brew install tmux # macOS
sudo apt install tmux # Ubuntu/Debian

Verify the install with:

tmux -V

You should see a version number—if not, check your package manager’s output for errors.

2. Start Your First Session

Launch Tmux with a named session (replace test with your project name):

tmux new -s test

You’ll see a green status bar at the bottom—this means you’re inside a Tmux session. Anything you run here will persist even if you disconnect.

3. Split Your Terminal into Panes

While inside Tmux, press Ctrl+B, then % to split the window vertically. Use Ctrl+B + arrow keys to navigate between panes. Here’s how to launch two Codex agents side by side:

# In the left pane:
codex --yolo

# Switch to the right pane (Ctrl+B → right arrow):
codex --yolo

Now you have two agents running in parallel—one could handle a refactor while the other builds a new feature.

4. Detach and Reattach (The Magic Feature)

To leave your session running without closing it, press Ctrl+B, then D (for "detach"). Your agents will keep running in the background. To reattach later:

tmux attach -t test

This works even if you close your terminal or switch networks—your VPS keeps everything alive.

5. Set Up Tmux on a VPS

SSH into your VPS (replace user@your-vps-ip with your credentials):

ssh user@your-vps-ip

Install Tmux on the VPS (same commands as above). Then start a new session:

tmux new -s ai-agents

Launch your agent inside the session—e.g., codex --yolo. Detach with Ctrl+B D, and your agent will run for days, even if you log out.

6. Use Slash Goals for Long-Running Tasks

Inside your agent (e.g., Codex or Hermes), use the /goal command to set a multi-hour task—like /goal build a 3D game shooter end-to-end. Tmux ensures the process won’t die when your laptop does.

Troubleshooting: Errors & Fixes

  • "Tmux command not found"—You didn’t install Tmux. Run brew install tmux (macOS) or sudo apt install tmux (Linux).
  • Can’t split panes—You’re not in a Tmux session. Start one with tmux new -s session-name.
  • Agent disconnects when detaching—Ensure you’re detaching with Ctrl+B D, not closing the terminal window.
  • VPS SSH connection drops—Use tmux attach -t session-name to reconnect. If the session died, check VPS uptime with uptime.

Where to Take This Further

  • Automate agent workflows—Write a script to launch multiple agents in separate Tmux panes, each with a different /goal.
  • Deploy full-stack apps—Use your VPS to host backend services (e.g., Node.js, Python) alongside your agents.
  • Monitor sessions—List active Tmux sessions with tmux ls and kill stale ones with tmux kill-session -t session-name.
  • Customize Tmux—Edit ~/.tmux.conf to change keybindings, colors, or status bar behavior (e.g., show CPU usage).

This setup puts you ahead of 99% of developers—most still run agents locally, losing progress when their laptop sleeps. With Tmux and a VPS, your agents work for you, not the other way around.
